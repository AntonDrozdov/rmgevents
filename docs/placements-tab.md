# Вкладка «Размещение»: пользовательская логика и архитектура

Документ описывает текущее поведение размещения в контексте мероприятия. Он состоит из двух частей:

1. инструкция и правила для пользователя системы;
2. техническое описание для разработчика с отдельными разделами по frontend и backend.

Термины:

- **объект размещения** — элемент схемы с названием, родителем, группой и необязательным количеством мест;
- **ЗАЛ** — отдельный тип объекта, который не имеет собственных мест и отображает дочерние объекты рядами;
- **ветка** — выбранный объект и все его потомки;
- **места объекта** — максимальное число гостей, назначенных непосредственно этому объекту;
- **группа объекта** — группа мероприятия, гости которой и всех её подгрупп допускаются к размещению;
- **шаблон** — общая между мероприятиями структура объектов без гостей и связей с группами.

Связанные разделы: [Группы](groups-tab.md), [Гости](guests-tab.md), [Категории](categories-tab.md).

# Часть 1. Для пользователя системы

## 1. Когда доступна вкладка

Вкладка **«Размещение»** доступна пользователям с разрешением `create_group` в выбранном мероприятии. Для создания нового гостя непосредственно из объекта дополнительно требуется `create_guest`.

В завершённом мероприятии структура доступна для просмотра: можно искать объекты, менять масштаб и открывать их параметры. Изменение объектов, назначения гостей и операции с шаблонами недоступны. Список гостей в форме объекта в этом режиме не загружается, но счётчики на карточках остаются видны.

## 2. Как устроена схема

У нового мероприятия структура размещения пуста. Первый объект создаётся кнопкой **«Создать объект размещения»** либо появляется после загрузки шаблона.

Схема отображается сверху вниз. На верхнем уровне может быть несколько объектов; обязательного единственного корня нет. Объекты соединены линиями, количество уровней определяется структурой. В заголовке отображается общее число объектов, включая скрытые поиском или сворачиванием.

Карточка объекта показывает:

- название, по нажатию на которое открывается форма;
- название связанной группы либо подсказку «Укажите группу»;
- действия создания дочернего объекта, редактирования и удаления ветки;
- кнопку сворачивания или раскрытия, если есть дочерние объекты.

Карточки оформлены в стиле блоков вкладки «Группы»: светлый фон, скруглённые углы и цветная полоса слева. В карточке показаны только название, группа и действия. У объектов с местами они отображаются квадратиками: закрашенные обозначают занятые места, светлые — свободные. Каждый квадратик соответствует конкретному номеру места: при назначении гостя сохраняется именно этот номер.

Квадратик места кликабелен для пользователя с разрешением `create_guest`. При наведении на занятый квадрат появляется карточка с ФИО и категорией гостя; её можно закрыть крестиком, и она появится снова только после нового наведения. Нажатие на свободное место открывает форму с двумя вкладками, начиная с **«Гости мероприятия»**. В ней отображается таблица уже заведённых гостей с ФИО, email и кнопкой «Добавить». Вкладка **«Новый гость»** содержит имя, email, телефон, группу, категорию и панель «Оригинальная структура» для заполнения имени из списка сотрудников. Нажатие на занятое место открывает форму редактирования гостя, который занимает это место. При сохранении объект размещения остаётся выбранным, а схема сразу обновляет занятость мест.

### Навигация

Поиск работает по названию без учёта регистра. Совпадения подсвечиваются, вместе с ними остаются видны их предки. При поиске ограничение глубины не скрывает найденные уровни, но вручную свёрнутую ветку нужно раскрыть.

Управление глубиной и масштабом находится справа внутри канвы, в том же виде, что у дерева групп. Кнопка `∞` показывает все уровни, цифры ограничивают глубину: `1` оставляет только верхний уровень, `2` — верхний уровень и его прямых потомков. Выбор уровня сбрасывает ручное сворачивание веток.

Кнопки `−` и `+`, а также колесо мыши меняют масштаб от 5% до 200% с шагом 10%. Полос прокрутки нет: схему можно перемещать мышью за свободное место вне карточек. Настройки вида не изменяют данные в базе.

## 3. Создание объектов

Чтобы создать объект:

1. нажмите **«Создать объект размещения»** для верхнего уровня или `+` на карточке родителя;
2. заполните название;
3. выберите количество и, при пакетном создании, начальный номер;
4. проверьте родительский объект;
5. выберите обязательную группу мероприятия;
6. укажите количество мест либо включите **«Без мест — гостей назначать нельзя»**;
7. нажмите **«Создать»**.

Начальные значения: один объект, начальный номер `1`, количество мест `10`. Группа автоматически не подставляется, в том числе при создании дочернего объекта.

| Поле | Правило |
|---|---|
| Название | Обязательно, до 140 символов; пробелы по краям удаляются при сохранении |
| Количество | От 1 до 100, используется только при создании |
| Начальный номер | Положительное целое число, используется при количестве больше 1 |
| Родительский объект | Выбранный объект либо «Верхний уровень» |
| Группа | Обязательная группа текущего мероприятия |
| Количество мест | Целое неотрицательное число либо режим «Без мест» |

При количестве `1` название сохраняется без номера. Например, название «Стол», количество `3` и начальный номер `7` создадут «Стол 7», «Стол 8», «Стол 9». У всех объектов пакета одинаковые родитель, группа и количество мест.

После создания одного объекта форма переключается на его редактирование и позволяет открыть вкладку «Гости». После пакетного создания форма закрывается; для назначения гостей нужно открыть конкретный объект.

## 4. Квоты и группы

### Контейнер рядов

Флажок **«Отображение ЗАЛ»** создаёт отдельный тип объекта. ЗАЛ создаётся одним пустым контейнером без дочерних объектов, не имеет собственных мест и не принимает гостей. В форме редактирования ЗАЛа поля его типа и мест не показываются: вместо них отображается пояснение.

На схеме ЗАЛ — одна общая панель: название и действия расположены сверху, дочерние объекты — вертикальными широкими рядами ниже. Название и группа ряда находятся слева, квадратики мест — в одну строку справа от названия, кнопки действий — справа. При большом числе мест ширина ряда и ЗАЛа увеличивается; внутренняя прокрутка не появляется.

При создании дочернего объекта внутри ЗАЛа количество мест обязательно и должно быть больше нуля. Режим «Без мест» и вложенный ЗАЛ для такого объекта недоступны. Пакетное создание позволяет создать несколько рядов с одинаковым количеством мест. Обычные назначения гостей работают для каждого ряда независимо.

Сервер применяет те же ограничения при редактировании и перетаскивании. Превратить существующий объект в контейнер можно только после снятия его гостей и при наличии мест у всех прямых дочерних объектов. Шаблоны сохраняют тип контейнера и места рядов.

Тип передаётся полем `displayChildrenAsRows` в `PlacementInput` и `PlacementView` и хранится в `placements.display_children_as_rows`. Миграция `20260924120000_AddPlacementRows` добавляет поле со значением `false` для существующих объектов; старые шаблоны также читаются как обычные объекты.

Количество мест относится только к текущему объекту. Гости и места дочерних объектов не расходуют места родителя и не ограничиваются ими.

Например, ЗАЛ может содержать два ряда по `10` мест. В ЗАЛ гостей назначить нельзя, а каждый ряд допускает до десяти гостей. Обычный родитель с числовым количеством мест также может принимать собственных гостей независимо от дочерних объектов.

Количество мест `0` допустимо, но свободных мест у такого объекта нет. Режим «Без мест» запрещает назначение гостей, а не означает неограниченную вместимость.

Объект принимает гостей выбранной группы и всех её подгрупп любой глубины. Иерархия объектов размещения и иерархия групп существуют независимо: группа дочернего объекта автоматически не наследуется.

## 5. Редактирование и перенос

Форма открывается по названию или карандашу. На вкладке **«Основное»** изменяются название, родитель, группа и количество мест. После успешного сохранения форма закрывается.

Сохранение отклоняется, если:

- количество мест меньше числа уже назначенных гостей;
- включён режим «Без мест» у занятого объекта;
- назначенные гости не входят в новую группу или её подгруппы;
- объект переносится внутрь самого себя или своей ветки;
- группа не выбрана.

Перенести объект можно выбором родителя в форме или перетаскиванием карточки на нового родителя. Для переноса на верхний уровень предусмотрена отдельная зона над схемой. Дочерняя ветка перемещается вместе с объектом.

Если объект загружен из шаблона и ещё не имеет группы, перетаскивание открывает форму с выбранным новым родителем. Нужно указать группу и сохранить изменение.

## 6. Назначение гостей

Откройте существующий объект и перейдите на вкладку **«Гости»**. Сначала сохраните изменения на вкладке «Основное»: назначения доступны только для сохранённого объекта с группой и числовым количеством мест. У ЗАЛа вкладки «Гости» нет.

Список содержит гостей выбранной группы и всех её подгрупп. В строке показаны имя, группа и текущее размещение либо «Без размещения». Поиск фильтрует список по имени без учёта регистра.

| Действие | Результат |
|---|---|
| «Назначить» | Гость без размещения занимает место в текущем объекте |
| «Перенести сюда» | Гость переходит из другого объекта, освобождая прежнее место |
| «Снять» | Гость остаётся в мероприятии без размещения |

Гость может занимать только один объект. При заполненных местах назначение и перенос в объект блокируются; снять уже назначенного гостя можно. Backend повторно проверяет вместимость при каждом запросе.

### Создание гостя из объекта

При наличии `create_guest` доступна кнопка **«Создать нового гостя»**. Укажите имя, обязательную категорию и при необходимости email и телефон, затем нажмите **«Создать и разместить»**.

Гость создаётся в группе текущего объекта и сразу получает размещение. При этом действуют обычные серверные проверки создания гостей, включая права пользователя и правила группы.

В основной форме на вкладке [«Гости»](guests-tab.md) также есть необязательное поле размещения. Назначения из обеих форм проверяются по одинаковым правилам квоты и принадлежности к группе.

## 7. Удаление и сброс

Кнопка удаления на карточке удаляет объект вместе со всеми потомками. Кнопка **«Сбросить»** удаляет всю структуру мероприятия.

Перед действием открывается модальное подтверждение с количеством затронутых объектов и гостей. После подтверждения объекты удаляются, размещение гостей снимается, сами гости сохраняются. Пока запрос выполняется, подтверждение нельзя закрыть.

## 8. Шаблоны

### Сохранение

Нажмите **«Сохранить шаблон»**, введите название длиной до 150 символов и подтвердите. Пустую структуру сохранить нельзя.

Шаблон содержит названия, иерархию и квоты объектов. Гости и связи с группами не переносятся. Сохранённые шаблоны доступны из других мероприятий.

### Загрузка

Нажмите **«Загрузить шаблон»**, выберите шаблон и подтвердите замену структуры. Текущие объекты будут удалены, а их гости останутся без размещения. Шаблон полностью заменяет структуру, а не добавляется к ней.

У загруженных объектов нет группы. Перед первым сохранением или назначением гостей выберите группу для нужного объекта. Названия, квоты и связи между родителями и потомками восстанавливаются из шаблона.

## 9. Связь с изменениями групп и ошибки

Перенос группы отклоняется, если после него уже размещённый гость перестанет принадлежать группе своего объекта или её подгруппам. При сбросе групп размещение гостей, перемещаемых в корневую группу, снимается.

Страница показывает состояния загрузки, пустой структуры, отсутствия результатов поиска и ошибок. Серверные сообщения о правилах размещения выводятся в странице или открытой форме; при другой ошибке используется общее сообщение с предложением повторить действие.

# Часть 2. Для разработчика

## 1. Модель данных и инварианты

```text
Event
  └── Placement[]
        ├── ParentId -> Placement (nullable)
        ├── GroupId -> Group (nullable)
        └── Guest[] через Guest.PlacementId

PlacementTemplate
  └── Structure: JSON со структурой PlacementView[]
```

### `corebackend.placements`

| Поле БД | Тип | Назначение |
|---|---|---|
| `id` | bigint, PK | Идентификатор объекта |
| `event_id` | bigint, FK | Мероприятие |
| `parent_id` | nullable bigint, FK | Родитель, `null` для верхнего уровня |
| `group_id` | nullable bigint, FK | Группа, `null` после загрузки шаблона или удаления связанной группы |
| `name` | varchar(150) | Название, включая номер при пакетном создании |
| `quota` | nullable integer | Вместимость; `null` запрещает назначения |
| `display_children_as_rows` | boolean | Признак ЗАЛа; по умолчанию `false` |

Удаление мероприятия и родительского объекта использует `CASCADE`. Удаление связанной группы использует `SET NULL`. Ограничение `placement_quota_nonnegative` допускает только `null` либо неотрицательную квоту. Созданы индексы по внешним ключам `event_id`, `parent_id`, `group_id`.

В `corebackend.guests` добавлены nullable `placement_id` и `placement_seat_number`. Номер места уникален в пределах объекта частичным уникальным индексом; при удалении или снятии размещения оба поля очищаются. Отдельной таблицы назначений нет; один гость хранит ссылку на объект и конкретный номер места.

### `corebackend.placement_templates`

Содержит `Id`, `Name` (до 150 символов), `Structure` (`jsonb`) и `CreatedAt` (`timestamp with time zone`). Поля `EventId` нет: шаблоны общие. В JSON сохраняются `PlacementView` с обнулёнными `GroupId` и `GuestCount`; прежние ID нужны для восстановления иерархии.

Основные инварианты:

1. объект, его родитель, связанная группа и назначаемый гость должны относиться к одному мероприятию;
2. цикл в структуре запрещён;
3. ручное создание и редактирование требуют группу;
4. назначение требует группу, числовую квоту и свободное место;
5. группа гостя входит в группу объекта или её поддерево;
6. `guestCount` и `occupiedSeatNumbers` считаются по прямым назначениям, без потомков;
7. удаление размещения сохраняет гостей;
8. импорт шаблона создаёт новые ID и оставляет группы пустыми.
9. ЗАЛ имеет `quota = null`, создаётся только в одном экземпляре и не принимает гостей;
10. прямой дочерний объект ЗАЛа обязан иметь положительное число мест и не может быть ЗАЛом.

Пути ниже указаны относительно корня репозитория.

## 3. Права доступа

Контроллер помечен `[Authorize]`. `CheckAccess` проверяет наличие группы текущего пользователя в мероприятии. Для операций записи дополнительно проверяются активность мероприятия через `IEventStateGuard` и разрешение `create_group`.

| Операция | Дополнительные требования |
|---|---|
| Чтение структуры и списка шаблонов | Участие пользователя в мероприятии |
| Получение допустимых гостей | Активное мероприятие и `create_group`, несмотря на HTTP GET |
| Создание, изменение, удаление, назначение, сохранение и загрузка шаблона | Активное мероприятие и `create_group` |
| Создание нового гостя | Отдельный Guests API и его проверки, включая `create_guest` |

Frontend защищает весь маршрут разрешением `create_group`, поэтому чтение через API доступно шире, чем сама вкладка. В `PlacementService` нет ограничения управления поддеревом группы текущего пользователя: принадлежность группы проверяется в пределах мероприятия. Это отличается от правил управления группами.

## 4. API

Базовый путь: `/api/events/{eventId}/placements`.

| Метод | Суффикс | Вход | Успешный ответ |
|---|---|---|---|
| GET | — | — | `PlacementView[]` |
| POST | — | `PlacementInput` | Полный обновлённый `PlacementView[]` |
| PUT | `/{id}` | `PlacementInput` | Полный обновлённый `PlacementView[]` |
| DELETE | `/{id}` | `confirmed` в query | `true` |
| DELETE | — | `confirmed` в query | `true`, сброс всей структуры |
| GET | `/guests` | `groupId` в query | `PlacementGuest[]` |
| PUT | `/{id}/guests/{guestId}` | `{ "remove": false }` либо `{ "remove": true }` | `true` |
| GET | `/templates` | — | Массив `{ id, name, createdAt }` |
| POST | `/templates` | `{ "name": "Название" }` | `true` |
| POST | `/templates/{id}/apply` | `confirmed` в query | Полный обновлённый `PlacementView[]` |

Для открытия занятого места frontend получает полную карточку гостя через `GET /api/events/{eventId}/guests/{guestId}`. Маршрут требует `CanCreateGuest`, возвращает `404`, если гость не относится к указанному мероприятию.

Все успешные действия контроллера возвращают `200 OK`, включая создание и удаление. `UnauthorizedAccessException` преобразуется в `403`, `InvalidOperationException` — в `400` с текстом ошибки. Отсутствие авторизации обрабатывается middleware.

`confirmed` по умолчанию равен `false`. Backend требует подтверждение удаления или замены, если затронуты назначенные гости. Frontend запрашивает подтверждение всегда и отправляет `confirmed=true`.

Снятие через `remove=true` обнуляет размещение только тогда, когда гость находится в указанном объекте. Если он находится в другом объекте, назначение сохраняется.

## 5. DTO

Пример создания двух объектов:

```json
{
  "name": "Стол",
  "parentId": 1,
  "groupId": 2,
  "quota": 10,
  "count": 2,
  "startNumber": 7
}
```

`PlacementInput` содержит `name`, nullable `parentId`, `groupId`, `quota`, `displayChildrenAsRows`, а также `count=1` и `startNumber=1`. При обновлении `count` и `startNumber` не используются. Nullable тип `groupId` нужен для модели импортированных объектов, но ручное сохранение без группы отклоняется.

Запросы создания и изменения гостя принимают необязательное `placementSeatNumber`. При передаче номера сервер закрепляет гостя за этим местом и отклоняет занятый или несуществующий номер. Если номер не передан, сервер выбирает первое свободное место; при обычном редактировании уже размещённого гостя его номер сохраняется.

`PlacementView` / frontend `Placement`:

```json
{
  "id": 5,
  "parentId": 1,
  "groupId": 2,
  "name": "Стол 7",
  "quota": 10,
  "guestCount": 3,
  "displayChildrenAsRows": false
}
```

`PlacementGuest` содержит `id`, `name`, `groupId`, `groupName`, nullable `placementId`. Список сортируется по имени. `List` возвращает объекты по ID; количество гостей вычисляется в SQL-проекции через `Count`.

## 6. Валидация и транзакции

`ValidateInput` проверяет название, квоту, группу и цепочку родителей внутри мероприятия. Для ЗАЛа дополнительно проверяются отсутствие собственных мест, создание только одного контейнера и положительное количество мест у прямых дочерних объектов. При обновлении дополнительно проверяются число и группы уже назначенных гостей. Пакетное создание ограничено 100 объектами; проверяется положительный начальный номер, переполнение диапазона `int` и длина итогового названия с номером до 150 символов.

`GroupScope` загружает группы мероприятия и собирает множество выбранной группы и её потомков. `ValidateGuest` проверяет существование объекта в мероприятии, группу, квоту и число занятых мест. При изменении существующего гостя он исключается из подсчёта, чтобы сохранение своего назначения не требовало дополнительного места.

Изменения выполняются через `Transaction`:

```text
ExecutionStrategy
  -> BeginTransaction
  -> pg_advisory_xact_lock(eventId)
  -> проверки и изменение данных
  -> Commit
```

Блокировка сериализует операции размещения в рамках мероприятия. Создание и редактирование гостей через `GuestService` используют тот же механизм, чтобы параллельные назначения через разные формы не превышали квоту. При уже открытой транзакции `Transaction` выполняет действие внутри неё без новой блокировки; вызывающий код должен учитывать это при добавлении новых путей записи.

Удаление собирает ID всей ветки, массово обнуляет `Guest.PlacementId` через `ExecuteUpdateAsync`, затем удаляет объекты. Применение шаблона выполняет удаление и восстановление в одной транзакции. Новые объекты создаются по уровням с отображением старых ID в новые. Некорректная структура без доступного следующего уровня вызывает ошибку и откат.

## 8. Frontend: состояние и обновление данных

| Состояние | Назначение |
|---|---|
| `items`, `groups`, `categories` | Объекты, дерево групп, категории для создания гостя |
| `loading`, `busy`, `error` | Загрузка, выполнение действия, сообщение об ошибке |
| `search`, `zoom`, `depth`, `collapsed` | Поиск и отображение дерева |
| `editing`, `formOpen`, `form`, `tab` | Редактируемый объект, форма и её вкладка |
| `guestList`, `guestLoading`, `guestSearch`, `guestVersion` | Список гостей, фильтр и повторная загрузка |
| `newGuest`, `showNewGuest` | Создание гостя внутри объекта |
| `templates`, `templateMode`, `templateName`, `templateId` | Сохранение и выбор шаблона |
| `confirmation` | Текст и действие модального подтверждения |

При открытии страницы `load` параллельно запрашивает объекты, группы и категории. Создание, обновление и применение шаблона заменяют `items` списком из ответа API. После удаления вызывается `load`; после назначения гостя повторно загружается структура и обновляется список гостей через `guestVersion`.

Список гостей загружается при открытой форме с выбранной группой и числовой квотой. При смене группы или закрытии формы устаревший ответ игнорируется через флаг активности эффекта.

`dirty` сравнивает название, группу, родителя и квоту с сохранённым объектом. `guestReady` разрешает назначения только для существующего объекта без несохранённых изменений, с группой, квотой и правом управления.

## 9. Миграция и проверки

Миграция `corebackend/src/Infrastructure/Migrations/20260922052854_AddPlacements.cs` добавляет таблицы объектов и шаблонов, поле `guests.placement_id`, внешние ключи, индексы и ограничение неотрицательной квоты. Миграция `20260924120000_AddPlacementRows` добавляет признак ЗАЛа `display_children_as_rows`. Снимок модели хранится в `ApplicationDbContextModelSnapshot.cs`.

Интеграционные проверки находятся в `corebackend/tests/PlacementChecks/Program.cs`. Для запуска из корня репозитория:

```powershell
$env:PLACEMENT_TEST_POSTGRES = 'Host=localhost;Port=5432;Database=postgres;Username=<user>;Password=<password>'
dotnet run --project corebackend/tests/PlacementChecks
```

Нужен PostgreSQL и пользователь с правом создания БД. Проверки создают отдельную базу `placement_checks_<GUID>`, применяют миграции и удаляют её в `finally`; рабочая база приложения не изменяется.

Проверяются пустая начальная структура, обязательность группы, пакетная нумерация, запрет циклов, места, смена группы, перенос гостей, независимость вместимости родителя и детей, подтверждение удаления, совместимость переноса группы, ЗАЛы и ряды, шаблоны и конкурентное назначение на последнее место.

Это проверки сервиса и БД: они не проверяют авторизацию контроллера и поведение браузерного интерфейса.

## 10. Текущие особенности и ограничения

- Названия объектов и шаблонов не имеют проверки уникальности.
- Обычные залы и столы различаются наличием мест; для контейнеров рядов хранится отдельный признак `DisplayChildrenAsRows`.
- Ручной порядок соседних объектов не сохраняется; API сортирует их по ID.
- Шаблоны не имеют владельца или привязки к мероприятию. API удаления и редактирования шаблонов отсутствует.
- Поле ввода названия ограничено 140 символами, а пакетное название с номером может достигать 150. Такое длинное автоматически созданное название потребуется сократить при последующем ручном сохранении.
- В завершённом мероприятии список гостей объекта не загружается: просмотр ограничен схемой, параметрами и счётчиками.
- Проверки мероприятия, циклов и совместимости групп выполняются сервисом; внешние ключи БД сами по себе не обеспечивают все эти правила.
